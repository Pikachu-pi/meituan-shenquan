# 安装与使用

适用于 Windows 10/11。支持美团神券活动 `80763916`，每日神券库存为 400 张。

## 首次安装

1. 将公开仓库克隆到固定目录，运行 [`scripts/install.cmd`](../scripts/install.cmd)。命令见 [快速开始](../README.md#快速开始)。也可以在资源管理器中双击该文件。
2. 按提示填写两个中台右上角显示的美团商家账号。密码和验证码在网页登录时填写。
3. 打开对应的桌面快捷方式，手动登录并核对账号，将门店范围切换到 **全部门店**，然后正常关闭窗口。

| 中台 | `-Brand` | 桌面登录快捷方式 | 默认端口 |
| --- | --- | --- | --- |
| 小仓 | `xiaocang` | 小仓中台登录（Edge） | `9335` |
| 乐心宜 | `lexinyi` | 乐心宜中台登录（Chrome） | `9334` |

两个浏览器分别保存登录资料，调试端口绑定本机。登录窗口设为 1920 × 1080，缩放系数为 1。日常运行复用各自的资料，以无头模式启动或连接浏览器。

首次安装直接运行 `install.cmd`。电脑只有 Windows PowerShell 5.1 时，安装器通过 Winget 另装 PowerShell 7，再用它执行后续步骤。若缺少 Winget，按安装器提示从微软官网安装 PowerShell 7 后重试。

后续步骤检测 Node.js 22.20+、Python 3.11+、Edge、Chrome、Browser Harness 和 Playwright CLI。缺失的软件通过 Winget 或依赖安装程序获取，首次安装需要联网。若公司策略限制安装或 Windows Script Host，联系 IT。安装器退出码为 `0` 表示成功，失败时保留窗口中的错误。

PowerShell 7 安装后，在仓库目录运行以下命令可单独检查环境。

```powershell
& .\scripts\setup.ps1 -CheckOnly
```

首次配置时，如果默认端口已被占用，核对占用进程后，用 `-XiaocangPort` 和 `-LexinyiPort` 指定两个空闲端口。重复安装保留现有端口、账号绑定和浏览器资料。移动项目后，检查桌面快捷方式指向的脚本路径，重新创建失效的入口。

## 核验登录并运行

在项目目录内使用 PowerShell 7。首次安装或重新登录后，先核验两边的账号。

```powershell
& .\scripts\Invoke-Shenquan.ps1 -Brand xiaocang -Mode VerifyLogin
& .\scripts\Invoke-Shenquan.ps1 -Brand lexinyi -Mode VerifyLogin
```

分别执行一次前置检查。确认全程无头运行，下载文件属于本次导出，门店数与页面一致，并停在取消和报名提交前。

```powershell
& .\scripts\Invoke-Shenquan.ps1 -Brand xiaocang -Phase preflight
& .\scripts\Invoke-Shenquan.ps1 -Brand lexinyi -Phase preflight
```

日常按任务选择中台和阶段。

| 阶段 | 行为 |
| --- | --- |
| `check-scope` | 核对账号，将门店范围切换到全部门店并再次核对 |
| `preflight`（默认） | 导出并核对当前报名 CSV，准备取消和报名表单，停在提交前 |
| `execute` | 提交批量取消，核对回执，再全选门店重新报名并回读结果 |

确认本次要实际取消并重新报名后，才使用 `-Phase execute`。同一中台同时运行一个任务。`-Mode Status` 仅查询浏览器进程与端口状态。

## 通过 Agent 调用

将完整项目目录安装为 Agent Skill。已有 `$dbs-install-skill` 时，让 Agent 用它安装本地目录。缺少该安装技能时，先执行官方安装命令，再回到 Agent 安装本项目。[dbskill 安装说明](https://github.com/dontbesilent2025/dbskill)

```powershell
npx -y skills add dontbesilent2025/dbskill -g --all
```

> 用 `$meituan-shenquan` 跑乐心宜神券活动前置，停在提交前。

## 结果与恢复

打开 `%LOCALAPPDATA%\MeituanShenquan\runs` 中的本次运行目录，先看 `结果.md`，再按需核对原始 CSV、逐店失败原因和平台回执。退出码 `0` 表示当前阶段完成，`1` 表示停止并需要核对，`2` 表示正式流程已完成回读且有门店报名失败。

| 情况 | 处理 |
| --- | --- |
| 账号不符、登录过期或验证码 | 用对应的桌面快捷方式重新登录。关闭窗口后再核验 |
| 可见登录窗口仍在运行 | 正常关闭该窗口，再运行无头流程 |
| 端口或运行锁被占用 | 核对进程和原任务，保留其运行状态 |
| CSV 缺列、ID 重复或数量不符 | 核对本次导出与页面，待修复后重跑前置 |
| 报名部分失败 | 按逐店原因处理。先确认原报名门店是否已恢复到生效中，且库存为 400 张 |

出现 `pending` 记录时，提交结果尚未核实。保留原目录和浏览器会话，用原 `-RunDir` 运行 `-Phase verify-cancel` 或 `-Phase verify-register` 核对对应回执。

出现 `active-run` 记录时，整轮业务尚未核实收尾。即使取消回执已确认，也要在原目录中继续核对报名回执和原门店恢复情况。待报名回执、门店、库存和状态均核对通过后，程序释放记录。

## 更新与迁移

升级前先处理运行锁、未决提交和未收尾任务。在现有仓库目录运行 `git pull --ff-only`。若依赖有变更，再运行 `scripts/install.cmd`。升级后重新核验两个账号，各跑一次前置检查。换电脑时重新克隆、安装并手动登录。
